# 🤖 Telegram-бот «Дневник Спокойного Материнства»

Простой Telegram-бот на Python (aiogram 3) для ведения дневника, развернутый на российской облачной платформе **Cloud.ru (Evolution)**. Бот работает без базы данных, состояние хранится в оперативной памяти.

## 📌 Особенности реализации

Проект изначально столкнулся с инфраструктурными ограничениями российских облаков (блокировка прямого доступа к `api.telegram.org`). Для обеспечения стабильной работы была разработана и внедрена отказоустойчивая архитектура с использованием сторонних сервисов-релеев.

### Архитектура взаимодействия

```text
[Пользователь Telegram]
       │
       ▼ (напрямую)
[Telegram API]
       ▲
       │ (через релей)
[Cloudflare Worker] ◄─── (запросы на отправку) ─── [Cloud.ru Container App]
       ▲                                                │
       │                                                │ (Webhook)
[BotGate] ◄─────────────────────────────────────────────┘
       ▲
       │ (пересылка обновлений)
[Telegram API]
```

## 🛠️ Задействованные сервисы и стек

### Язык и библиотеки

- Python 3.11
- aiogram 3.13+ (асинхронный фреймворк для Telegram Bot API)
- aiohttp (для приема вебхуков)
- Docker (сборка под платформу `linux/amd64`)

### Инфраструктура (внешние сервисы)

- 🔵 **Cloud.ru (Evolution Container Apps)** — основная среда хостинга. Сюда упакован Docker-образ с ботом. Контейнер принимает вебхуки от BotGate.
- 🔵 **BotGate (bot-gate.ru)** — специализированный шлюз (Webhook Relay), который принимает обновления от Telegram и пересылает их на сервер в Cloud.ru. Это решает проблему блокировки входящих соединений.
- 🔵 **Cloudflare Workers** — исходящий релей (Reverse Proxy). Поскольку контейнер в Cloud.ru не может напрямую обратиться к `api.telegram.org` для отправки ответов, он отправляет запросы на Cloudflare Worker, который, в свою очередь, перенаправляет их в Telegram.

## 🚀 Ключевые особенности кода

- **Обход блокировок:** в `bot.py` принудительно переопределен базовый адрес API Telegram (`TelegramAPIServer.from_base("https://tg-relay.lev841243.workers.dev")`), чтобы все исходящие запросы шли через Cloudflare Worker.
- **Webhook-сервер:** бот запускает веб-сервер на aiohttp (порт 8080), который принимает POST-запросы от BotGate по корневому пути `/`.
- **Безопасность (No DB):** данные не пишутся на диск. Состояние сессии (`FSMContext`) хранится в `MemoryStorage` и удаляется после завершения опроса или отмены.
- **Переменные окружения:** токен бота передается строго через переменную `BOT_TOKEN` в настройках Cloud.ru (не хранится в коде).

## 📦 Инструкция по развертыванию и обновлению

1. **Сборка образа:**

   ```bash
   docker build --tag dnevnik-bot-registry.cr.cloud.ru/bot:vX --platform linux/amd64 .
   docker push dnevnik-bot-registry.cr.cloud.ru/bot:vX
   ```

2. **Создание ревизии:** в Cloud.ru (Container Apps) создается новая ревизия с указанием дайджеста нового образа.
3. **Переменные:** в переменных контейнера обязательно должен быть указан `BOT_TOKEN`.
4. **Привязка Webhook:** в панели BotGate в поле «Пересылка вебхуков» указывается публичный URL контейнера из Cloud.ru (без пути `/webhook`, так как используется корень).
